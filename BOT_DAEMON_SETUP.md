# 🤖 Настройка постоянной работы Telegram бота

Этот документ описывает различные способы запуска Telegram бота для постоянной работы, независимо от состояния терминала.

## 🚀 Быстрый старт

Запустите главный скрипт управления:
```bash
./manage_bot.sh
```

Выберите нужный режим работы из меню.

## 📋 Варианты запуска

### 1️⃣ Системный сервис (LaunchAgent) - РЕКОМЕНДУЕТСЯ
**Автоматический запуск при загрузке системы**

```bash
./manage_bot.sh 1
# или
./install_daemon.sh
```

**Преимущества:**
- ✅ Автоматически запускается при загрузке macOS
- ✅ Работает даже после перезагрузки
- ✅ Управляется системой macOS
- ✅ Автоматический перезапуск при сбоях

**Управление:**
```bash
./daemon_status.sh      # Проверить статус
./daemon_restart.sh     # Перезапустить
./uninstall_daemon.sh   # Удалить сервис
```

### 2️⃣ Демон с автоперезапуском
**Работает в фоне, перезапускается при сбоях**

```bash
./manage_bot.sh 2
# или
./start_daemon.sh
```

**Преимущества:**
- ✅ Автоматический перезапуск при сбоях
- ✅ Подробное логирование
- ✅ Контроль количества перезапусков
- ✅ Работает в фоне

**Управление:**
```bash
./status_daemon.sh      # Проверить статус
./stop_daemon.sh        # Остановить
```

### 3️⃣ Фоновый режим (nohup)
**Простой фоновый запуск**

```bash
./manage_bot.sh 3
# или
./start_background.sh
```

**Преимущества:**
- ✅ Простота использования
- ✅ Работает в фоне
- ✅ Логирование в файлы

**Управление:**
```bash
./status_background.sh  # Проверить статус
./stop_background.sh    # Остановить
```

### 4️⃣ Обычный запуск
**В текущем терминале**

```bash
./manage_bot.sh 4
# или
python3 bot_manager.py start
```

**Использование:** Только для тестирования и разработки.

## 📁 Файлы и логи

### Системный сервис
- `bot.log` - основные логи бота
- `bot_error.log` - логи ошибок
- `~/Library/LaunchAgents/com.telegram.bot.plist` - конфигурация сервиса

### Демон
- `daemon.log` - логи демона
- `daemon_output.log` - вывод демона
- `daemon.pid` - PID демона

### Фоновый режим
- `logs/bot_YYYYMMDD_HHMMSS.log` - логи бота
- `bot_background.pid` - PID фонового процесса

## 🔧 Устранение проблем

### Ошибка "Conflict: terminated by other getUpdates request"
Эта ошибка возникает при запуске нескольких экземпляров бота.

**Решение:**
```bash
# Остановить все боты
./manage_bot.sh 5

# Подождать 5 секунд
sleep 5

# Запустить нужный режим
./manage_bot.sh 1  # или 2, или 3
```

### Проверка запущенных процессов
```bash
# Показать все процессы Python
ps aux | grep python

# Показать процессы бота
ps aux | grep bot_final.py
```

### Очистка файлов блокировки
```bash
# Удалить все файлы блокировки
rm -f bot.lock bot_manager.lock bot.pid daemon.pid bot_background.pid
```

## 🎯 Рекомендации

1. **Для продакшена:** Используйте системный сервис (вариант 1)
2. **Для разработки:** Используйте демон с автоперезапуском (вариант 2)
3. **Для тестирования:** Используйте фоновый режим (вариант 3)

## 📞 Поддержка

При возникновении проблем:
1. Проверьте статус: `./manage_bot.sh 6`
2. Посмотрите логи: `./manage_bot.sh 7`
3. Остановите все боты: `./manage_bot.sh 5`
4. Запустите заново: `./manage_bot.sh 1`
